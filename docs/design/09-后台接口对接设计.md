> 后台代码位置：`/Users/apple/v2`（`internal/api/router/router.go` 为路由权威来源）

## 9.1 通用约定

### 9.1.1 请求

| 项 | 值 |
|---|---|
| Base URL | `https://new.moneyfly.top/api/v1` |
| 认证 | `Authorization: Bearer {access_token}` |
| CSRF | 所有 POST/PUT/PATCH/DELETE（除 `/auth/*`）携带 `X-CSRF-Token`；从 `GET /csrf-token` 获取，**单次有效，后端每次校验成功后轮换** |
| 设备标识 | `X-App-Device-Id: {HWID}`（每个请求都带） |
| User-Agent | `Mclash/{版本} ({OS特征串})` |
| 设备详情头 | `X-MF-*`（型号/品牌/OS/类型），保证 UA 被截断或解析不全时后台仍能准确识别设备 |
| Content-Type | `application/json; charset=UTF-8` |

### 9.1.2 响应

```json
{ "code": 0, "message": "success", "data": { ... } }
```

分页：`data: { "items": [...], "total": 100, "page": 1, "page_size": 20 }`

### 9.1.3 错误码与客户端处理

| code | 含义 | 客户端处理 |
|---|---|---|
| `0` | 成功 | — |
| `40000` | 请求参数错误 | 显示 `message` |
| `40100` | 未登录 / Token 失效 | **静默 refresh**；失败 → `onSessionExpired()` → 清路由栈回登录页 |
| `40300` | 无权限 / CSRF 无效 | 显示 `message`；若是 CSRF 失效 → 重新取 token 并**重放一次** |
| `40400` | 资源不存在 | 显示 `message` |
| `40900` | 资源冲突 | 显示 `message` |
| `42900` | 请求过于频繁 | 「操作过于频繁，请稍后再试」+ 按钮倒计时 |
| `50000` | 服务器错误 | 「服务器开小差了，请稍后重试」 |

### 9.1.4 网络层错误文案（统一实现）

| 条件 | 文案 |
|---|---|
| 后端带 `message` / `detail` / `error` | 原样显示（这是「账户已被禁用…」「此设备已被移除并踢下线…」到达前端的路径） |
| 连接超时 / 连接错误 | 网络连接失败，请检查网络后重试 |
| 接收超时 | 服务器响应超时，请稍后重试 |
| 发送超时 | 发送请求超时，请稍后重试 |
| 请求取消 | 请求已取消 |
| HTTP 401 | 登录已过期，请重新登录 |
| HTTP 403 | 没有权限执行此操作 |
| HTTP 404 | 请求的资源不存在 |
| HTTP 429 | 操作过于频繁，请稍后再试 |
| HTTP 500 | 服务器开小差了，请稍后重试 |
| 其他状态 | 请求失败（{code}） |
| `FormatException` | 数据解析失败 |
| 订阅返回 zip | 订阅返回的是 zip 压缩包，请在服务端改为直接返回 Clash 配置 |

> 🔧 **改造点**：以上 13 条文案在 baseline 中**硬编码中文**，必须全部迁移到 `AppStrings`（en 语言下目前会露出中文）。

### 9.1.5 并发 401 处理

```
请求 A ─┐
请求 B ─┼─ 同时 401 ─→ 只允许 1 个 refresh 在途，其余等待其结果
请求 C ─┘             → 成功：全部重放；失败：统一触发 onSessionExpired
```

**必须**：防止 refresh token 被并发消费多次 → 全部失效 → 用户被强制登出。

**密码策略**（与后端 `auth.ValidatePasswordStrength` 逐字对齐）

```
specials = !@#$%^&*()_+-=[]{}|;:,.<>?
kindsOf(pwd) → 统计 大写 / 小写 / 数字 / 符号 四类命中数（0..4）
errorFor(pwd):
  len < 8      → 「密码至少 8 位」
  kinds < 3    → 「密码强度不足：需包含大小写字母、数字、特殊字符中的至少三种」
  否则         → null
hint = 「至少 8 位，大小写字母/数字/符号至少三种」
```

**邮箱格式**：`^[\w.+-]+@[\w-]+(\.[\w-]+)+$`（trim 后校验）

## 9.3 订阅模块（核心）★

### 9.3.1 订阅元信息

```
GET /user/subscribe          （XBoard 兼容别名）
GET /subscriptions/user-subscription   （原生路由）
```

| 响应字段 | 类型 | 用途 |
|---|---|---|
| `subscribe_url` | string | **订阅内容地址**（下一步去拉取它） |
| `universal_url` | string? | 通用（非 Clash）订阅地址 |
| `expire_time` | string | 到期时间 |
| `device_limit` | int | 设备上限 |
| `current_devices` | int | 当前在线设备数 |
| `remaining_days` | int | 剩余天数 |
| `is_expired` | bool | 是否到期 |
| `status` | string | 订阅状态 |
| `is_active` | bool | 订阅是否启用 |

**判定逻辑**

```dart
bool get hasSubscription => status == 'active' && !isExpired && isActive;
```

| 情况 | 处理 |
|---|---|
| `subscribe_url` 为空 | **尚未开通套餐** → 空节点 + 「去开通」CTA |
| `hasSubscription == false` | **账号受限** → `_dropAllCaches()` 清空一切 → 首页红色横幅 + 连接门禁 |

### 9.3.2 订阅内容拉取（**不走 API 网关的 JWT**）

```
GET {subscribe_url}?token={token}
```

> 这是**独立于 `/api/v1` 的公开端点**（`GET /api/v1/client/subscribe?token=TOKEN`），
> 自动识别客户端并返回对应格式。

| 请求头 | 值 |
|---|---|
| `User-Agent` | `Mclash/{版本} ({OS})`；**或用户自定义**（设置页「订阅 User-Agent」，留空用默认） |
| 其他 | 不携带 JWT |

**为什么允许自定义 UA**：部分机场按 UA 返回不同客户端格式，用户需要能自救。

### 9.3.3 三种响应形态（自动识别，用户无需选择）

| 形态 | 识别 | 处理 |
|---|---|---|
| Clash YAML | `loadYaml` 返回 `Map` 且 `proxies` 是 `List` | 直接读 `proxies` |
| base64 整包 | `loadYaml` 返回 `String` 标量 | 宽松解码 → 若含 `proxies:` 再解一层 YAML；否则按链接列表逐行解析 |
| 明文链接列表 | 每行 `scheme://` | 逐行解析 |

**base64 宽松解码必须处理的噪声**（`_b64DecodeLoose`）：

| 噪声 | 处理 |
|---|---|
| 末尾换行 / CRLF / 制表 / 空格 | 剥离全部空白 |
| 76 字符折行 | 同上 |
| 零宽空格 `\u200b` / BOM `\ufeff` | 剥离 |
| URL-safe 字母表（`-` `_`） | 归一化 `+` `/` |
| 缺少 `=` 填充（`len % 4 == 1` 非法除外） | 补齐 |
| 混入非法字节（GBK 注释） | `allowMalformed: true` 兜底 |

> ⚠️ Dart 的 `base64.normalize` 遇到**任何**非 base64 字符直接抛 `FormatException`。
> 未清洗就调用 + 异常被吞 → **整份订阅静默解析成 0 个节点**（用户看到「没节点」，日志无报错）。

### 9.3.4 占位伪节点（后台在受限时下发）

| 特征 | 值 |
|---|---|
| `server` | `baidu.com` |
| `name` 含 emoji | `📢`（官网）`⏰`（到期）`📱`（设备）`💬`（客服）`🎯` `🚀` `♻️` `🔯` `🔮` `🛑` `🐟` |

**处理**：必须过滤掉（不显示、不参与测速/连接）；
但**必须用它覆盖**本地缓存（不能因为「解析结果为空」就跳过覆盖，否则过期用户仍能用缓存里的可用线路）。

### 9.3.5 订阅链接的其他路由（后台已支持，客户端本期不用）

| 路径 | 说明 |
|---|---|
| `GET /api/v1/subscribe/:url` | 兼容旧订阅地址（旧 token 映射到当前订阅记录，仍受状态/到期/设备数控制） |
| `GET /api/v1/sub/*path` | 同上 |

> 客户端**只使用** `subscribe_url` 下发的完整地址，不自行拼接 —— 保证后台可以随时改路由而无需发版。

**被踢下线的识别（重要）**

```

  「此设备已被移除并踢下线…」
客户端判定（SubscriptionService.isKickedMessage）：
  msg.contains('已被移除') || msg.contains('踢下线')
  || msg.toLowerCase().contains('removed') || msg.toLowerCase().contains('kicked')
→ 处理：清空订阅缓存 + 断开连接 + 首页红色横幅「本设备已被移除」+「重新登录」
```
