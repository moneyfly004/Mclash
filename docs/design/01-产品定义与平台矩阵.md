# 01 · 产品定义与平台矩阵

> Mclash —— MoneyFly 多平台加速客户端
> 文档版本 v1.0 · 状态：待评审 · 对应项目 `github.com/moneyfly004/Mclash`

---

## 1.1 一句话定义

**Mclash 是一款「装完就可用」的商用加速客户端：用户不接触订阅、不接触配置、不接触内核，
只要登录账号，软件自动把后台（`https://new.moneyfly.top`）的订阅拉下来、自动测速挑出最快线路、
一键连上。所有复杂度都留在后台与客户端内部。**

---

## 1.2 三条不可动摇的设计原则

| 原则 | 含义 | 反例（明确不做） |
|---|---|---|
| **P1 · 零配置** | 用户永远不需要看到/粘贴订阅链接、不需要选 YAML、不需要装内核。订阅地址由后台随账号下发。 | ❌ 首屏放一个「导入订阅」输入框<br>❌ 让用户选「Clash / V2Ray / 通用」订阅格式 |
| **P2 · 一键** | 主界面只有一个主动作按钮（连接/断开）。其余全部自动。 | ❌ 连接前先弹「请选择节点」<br>❌ 连接后又要求手动点「应用」 |
| **P3 · 简洁** | 主界面信息密度低、层级浅（≤4 个顶级 Tab）。高级能力（改端口、改 DNS、TUN、分流）默认折叠进设置，且都有安全默认值。 | ❌ 把规则编辑器/代理组编辑器放到一级界面<br>❌ 主界面出现 10 个以上可点击元素 |

> **不做「通用代理工具」，只做「MoneyFly 的官方客户端」。**
> 这是与 Clash Mi / Clash Verge / FlClash 的根本分野 —— 后者是通用工具，
> 本产品是**业务客户端**，一切围绕「登录 → 连上 → 续费」这条闭环。

## 1.3 平台矩阵（本期交付范围）

| 平台 | 架构 | 分发形态 | 内核形态 | 系统最低版本 | CI Runner |
|---|---|---|---|---|---|
| **Android** | `arm64-v8a` | APK（分 ABI） | **进程内** `libmihomo.aar`（gomobile bind，VpnService TUN fd 注入） | Android 8.0 (API 26) | `ubuntu-latest` |
| **Android** | `armeabi-v7a` | APK（分 ABI） | 同上 | Android 8.0 (API 26) | `ubuntu-latest` |
| **Android** | `x86_64` | APK | 同上 | Android 8.0 (API 26) | `ubuntu-latest` |
| **Android** | — | AAB（商店备用） | 同上 | Android 8.0 (API 26) | `ubuntu-latest` |
| **Windows** | `amd64` | `.exe` 安装包（Inno Setup）+ `.zip` 便携版 | **子进程** `mihomo.exe`（官方内核，随包内置） | Windows 10 (1809+) | `windows-latest` |
| **macOS** | `arm64`（Apple 芯片 / M 系列） | `.dmg` | **子进程** `mihomo`（官方 `mihomo-darwin-arm64`） | macOS 11 Big Sur | `macos-14` |
| **macOS** | `x86_64`（Intel） | `.dmg`（**原生 x86_64 构建，非 universal 裁剪**） | **子进程** `mihomo`（官方 `mihomo-darwin-amd64-compatible`） | macOS 10.15 Catalina（建议 11+） | `macos-14` + Rosetta 全链 |
| **macOS** | `universal`（可选） | `.dmg` | 双架构 `lipo -create` 合并的内核 | macOS 11+ | `macos-14` |

### 为什么 macOS 必须区分 Apple 芯片 / Intel

1. **内核指令集不同**：官方 `mihomo-darwin-amd64` 要求 **AMD64 v3（AVX2）** 指令集。
   2015 年前的 Intel Mac、以及 Rosetta 转译层都不支持 —— 直接启动即崩。
   因此 Intel 端**必须**使用官方 `mihomo-darwin-amd64-compatible` 构建。
2. **Flutter 引擎架构自洽**：`universal` 包在旧 Intel 机器上出现过「引擎自身仅 arm64」的坏包。
   本设计对 Intel 采用 **Rosetta 全程 x86_64 构建链**（`arch -x86_64 flutter build macos --release`），
   产出**纯 x86_64** 快照，再用 `lipo -verify_arch x86_64` 断言，杜绝「半 arm 半 x86」。
3. **发布页面必须让用户选对包**：Release 资产命名带架构后缀，正文用加粗提示「请勿跨架构混装」。

### 本期不做（范围外，但架构预留）

| 平台 | 状态 | 说明 |
|---|---|---|
| iOS | 架构预留，**本期不交付** | 需要 `packet-tunnel-provider` entitlement（苹果仅付费开发者账号签发）。内核走 `Mihomelib.xcframework` + `PacketTunnel.appex`，代码路径已存在，可在后续里程碑打开。 |
| Linux | 架构预留，**本期不交付** | 内核走 `mihomo` 子进程，与 Windows/macOS 同一条 `ProxyCoreCli` 代码路径，仅需补打包脚本。 |

## 1.5 用户核心旅程（North Star Flow）

```
① 安装 → 打开 App
        ↓  （无任何配置引导）
② 登录（邮箱 + 密码）           ← 唯一一次手动输入
        ↓  自动：拉订阅 → 解析节点 → 并发测速 → 选出最快
③ 点一下大按钮「连接」           ← 唯一一次手动点击
        ↓  自动：启动内核 → 就绪探测 → 置系统代理
   ✅ 已连接，可上网
```

**量化目标**

| 指标 | 目标值 |
|---|---|
| 从点「登录」到「节点列表可用」 | ≤ 5s（弱网除外） |
| 从点「连接」到「已连接」 | ≤ 3s |
| 冷启动到首屏可交互 | ≤ 1.5s（先用本地缓存秒显） |
| 冷启动到节点列表可见 | ≤ 800ms（读磁盘缓存，零网络） |
| 主界面单屏可点击元素 | ≤ 7 个 |
| 用户从安装到上网的操作次数 | **2 次**（登录 + 连接） |

## 1.6 与两个参考项目的取舍决策

本项目的两个输入：`clashmi-main`（Clash Mi 前端壳）与 `mysoftware/moneyfly`（MoneyFly 业务客户端）。

### 1.6.1 事实核查结论

| 维度 | clashmi-main | mysoftware/moneyfly |
|---|---|---|
| Dart 文件数 | 147 | 112 |
| 是否可直接构建 | ❌ **否** | ✅ **是** |
| 内核集成 | ❌ 缺失（`bind/*` 全被 gitignore；依赖外部 `../libclash-vpn-service`、`../board-service` 两个不存在的兄弟目录） | ✅ 完整（`android/mihomo-core` 源码 + `libmihomo.aar` + `tools/fetch_mihomo.sh` + CI 内置内核） |
| CI | ❌ **完全没有**（`.github/` 只有 issue 模板） | ✅ 完整（Android 分 ABI + AAB / Windows exe+zip / macOS arm64+x64+universal / iOS IPA） |
| 业务功能 | 通用代理工具（profile/规则/代理组/zashboard/webdav） | MoneyFly 业务闭环（登录/订阅/套餐/支付/设备/工单/通知） |
| 多平台目录 | android / windows / macos / linux / ios | android / windows / macos / ios |
| 架构缺陷 | `org.gradle.java.home` 硬编码 Windows 路径；signing 指向不存在的 keystore；macOS 缺 `clashmiService` target | — |

### 1.6.2 决策：**以 moneyfly 为落地基线，以 clashmi 为工程与 UX 参照**

> **决策 ADR-001**
> Mclash 的代码基线取自 `mysoftware/moneyfly`，因为它已经**在本机验证可构建、可发布**，
> 且已经满足本产品全部 P0 要求（自动拉订阅 / 自动测速 / 一键连接 / 三平台 + macOS 双架构）。
> `clashmi-main` 作为**参照系**：借鉴其多平台工程组织方式、VpnService 前台服务健壮性细节、
> 以及少数值得吸收的 UX 模式（快捷磁贴、控制中心开关、内核日志实时页）。
>
> **理由**：`clashmi` 缺 8 项外部二进制输入（AAR / xcframework / Windows core / 两个 Dart 插件包），
> 从零重建这些产物的成本远高于「把 moneyfly 的 UI 改造得更像 clashmi」。
> 而本产品的用户是**付费订阅用户**，不是折腾配置的玩家 —— clashmi 的通用工具能力
> （规则编辑器、代理组编辑器、多 profile、WebDAV 同步）与本产品的 P3「简洁」原则直接冲突。

### 1.6.3 从 clashmi **吸收**的具体项

| # | 吸收项 | 落地位置 | 价值 |
|---|---|---|---|
| A-01 | 前台服务通知的健壮性处理（`START_STICKY` 无配置自停、防「幽灵连接」） | `MoneyFlyVpnService` 同款逻辑保留 | 已在 baseline 中，冻结不改 |
| A-02 | 快捷设置磁贴（Quick Settings Tile） | 新增 Android `TileService` | 下拉面板一键连接/断开 |
| A-03 | 系统级「控制中心开关」（macOS/iOS） | 后置（P1） | 桌面快捷开关 |
| A-04 | 内核日志**实时流**页（按级别过滤 + 语义说明） | 并入 F-12 日志中心 | 排障体验 |
| A-05 | 深度链接 scheme 处理（`mclash://`） | 本期只保留 `mclash://connect` | 后续扫码联动 |
| A-06 | 应用内 WebView（用户协议 / 官网 / 帮助 / 内嵌支付页） | 设置与我的页入口 | 减少外跳 |
| A-07 | 全平台字体/emoji 兜底（Emoji 字体 + 国旗 PNG 兜底） | 节点列表国旗 | Windows 上 emoji 国旗显示为字母的问题 |

### 1.6.4 从 clashmi **明确不吸收**的项

- 代理组 / 规则 / 规则集编辑器（违背 P3）
- 多 profile 与订阅导入入口（违背 P1）
- WebDAV / iCloud / 局域网同步（不在业务范围内，且引入配置泄漏面）
- 内嵌 zashboard 作为一级功能（可作为 P2 的「高级面板」入口）
- `libclash_vpn_service` 插件体系（其 AAR 与 xcframework 均不可得；改用自有的 `android/mihomo-core` + 官方内核二进制）

## 1.7 术语表

| 术语 | 含义 |
|---|---|
| **内核 / Core** | mihomo（MetaCubeX/mihomo，原 Clash.Meta）。本项目**不使用 fork**，一律用官方源码/官方预编译产物 |
| **AAR** | `libmihomo.aar` —— 官方 mihomo 经 `gomobile bind` 编译的 Android 库，仓库 `moneyfly004/mihomo-lib` |
| **订阅拉取** | 客户端用后台下发的 `subscribe_url` 取回 Clash YAML / base64 / 链接列表，解析成节点 |
| **占位节点** | 后台在账号到期/禁用时下发的**虚假节点**（`server: baidu.com`，名字带 📢⏰📱💬 等 emoji）。客户端必须识别并过滤，且**必须用它覆盖**本地缓存 |
| **准入闸门** | `AccountService` 对「到期 / 订阅停用 / 账号禁用 / 设备被踢」的统一判定，位于连接之前 |
| **一键连接** | 用户点击后完整链路：准入判定 → 生成 YAML → 启动内核 → 就绪探测 → 置系统代理 |
| **就绪探测** | 不能只看 Clash API 返回 200；还需本地端口（mixed 入站口）真的有人在监听，否则会出现「界面已连接、浏览器打不开」 |
| **出口定位** | 连接后经隧道查询真实出口 IP → 国家/城市，用于首页展示 |
| **兼容版内核** | 官方 `*-compatible` 构建，不要求 AVX2/v3 指令集，用于老 Intel CPU / Rosetta / 老 AMD CPU |
