# 01 · 产品定义与平台矩阵

> 文档版本 **v2.0**（v1.0 的三条原则「零配置/一键/简洁」与「明确不做」清单已废弃）
> 对应项目 `github.com/moneyfly004/Mclash`

## 1.1 一句话定义

> **Mclash = Clash Mi 的界面与全部代理能力 + MoneyFly 的账号与商业化闭环。**
>
> 用户在 Clash Mi 那套熟悉的界面里登录 MoneyFly 账号，订阅**自动**从后台
> `https://new.moneyfly.top` 拉下来并落到「我的配置」，**自动**测速选优，**一键**连接。
> 同时 Clash Mi 原有的代理管理、分流、内核设置、应用设置、备份同步、网络检测等能力**一个不少**。

## 1.2 三条设计原则（v2.0 重写）

| 原则 | 含义 | 与 v1.0 的差异 |
|---|---|---|
| **P1 · 风格是 Clash Mi 的** | 视觉、排版、交互、组件全部沿用 Clash Mi：Material 3 + 种子色 `#293CA0` + 方角 + 高密度列表 + 单页滚动首页。**不做视觉再设计。** | v1.0 曾自己设计了一套圆角渐变风格 —— **错误，已废弃** |
| **P2 · 能力是 Clash Mi 的** | Clash Mi 的功能**默认全部保留**。可以砍的只有明确列出的 2 项（面板 zashboard、二维码工具）。任何"简化"都必须先经确认。 | v1.0 有一条"明确不做"清单（代理组/规则/多配置/同步等）—— **错误，已废弃** |
| **P3 · 开箱即用是 MoneyFly 的** | 订阅不需要用户导入（后台随账号下发）；连接不需要选节点（自动测速选优）；续费/设备/通知都在这一个 App 里。 | 与 v1.0 一致，但**不以此为由删除任何现有能力** |

### 三者的关系

```
└─────────────────────────────────────────────────────────────┘
```

## 1.3 平台矩阵（本期交付范围）

| 平台 | 架构 | 分发形态 | 内核形态 | 系统最低版本 | CI Runner |
|---|---|---|---|---|---|
| **Android** | `arm64-v8a` | APK（分 ABI） | **进程内** `libmihomo.aar`（gomobile bind，VpnService TUN fd 注入） | Android 8.0 (API 26) | `ubuntu-latest` |
| **Android** | `armeabi-v7a` | APK（分 ABI） | 同上 | Android 8.0 (API 26) | `ubuntu-latest` |
| **Android** | `x86_64` | APK | 同上 | Android 8.0 (API 26) | `ubuntu-latest` |
| **Android** | — | AAB（商店备用） | 同上 | Android 8.0 (API 26) | `ubuntu-latest` |
| **Windows** | `amd64` | `.exe` 安装包（Inno Setup）+ `.zip` 便携版 | **子进程** `mihomo.exe`（官方 compatible） | Windows 10 (1809+) | `windows-latest` |
| **macOS** | `arm64`（Apple 芯片） | `.dmg` | **子进程** `mihomo`（官方 `mihomo-darwin-arm64`） | macOS 11 Big Sur | `macos-14` |
| **macOS** | `x86_64`（Intel） | `.dmg`（**原生 x86_64 构建**） | **子进程** `mihomo`（官方 `mihomo-darwin-amd64-compatible`） | macOS 10.15（建议 11+） | `macos-14` + Rosetta 全链 |
| **macOS** | `universal` | `.dmg` | 双架构 `lipo -create` 合并 | macOS 11+ | `macos-14` |

### 为什么 macOS 必须区分 Apple 芯片 / Intel

1. **内核指令集不同**：官方 `mihomo-darwin-amd64` 要求 **AMD64 v3（AVX2）**。2015 年前的 Intel Mac
   与 Rosetta 转译层都不支持 → 启动即崩。Intel 端**必须**用 `mihomo-darwin-amd64-compatible`。
2. **Flutter 引擎架构自洽**：`universal` 包在旧 Intel 机器上出现过「引擎自身仅 arm64」的坏包。
   Intel 端采用 **Rosetta 全程 x86_64 构建链**（`arch -x86_64 flutter build macos --release`），
   产出纯 x86_64 快照，再用 `lipo -verify_arch x86_64` 断言。
3. **发布页必须让用户选对包**：资产名带架构后缀 + 正文加粗提示「请勿跨架构混装」。

### 本期不做（但架构预留）

| 平台 | 状态 | 说明 |
|---|---|---|
| iOS | 架构预留，**本期不交付** | 需 `packet-tunnel-provider` entitlement（苹果仅付费开发者账号签发）。内核走 `Mihomelib.xcframework` + `PacketTunnel.appex`，代码路径已在 baseline 中存在。 |
| Linux | 架构预留，**本期不交付** | 与 Windows/macOS 同一条 `ProxyCoreCli` 路径，仅需补打包脚本。 |

## 1.5 用户核心旅程

### 1.5.1 首次使用（North Star Flow）

```
① 安装 → 打开
        ↓
② 登录 MoneyFly 账号（邮箱 + 密码）      ← 唯一一次手动输入
        ↓  自动：拉订阅 → 解析节点 → 写入「我的配置」→ 并发测速 → 选中最优
③ 首页连接开关拨到「开」                  ← 唯一一次手动操作
        ↓  自动：准入判定 → 生成 YAML → 启动内核 → 就绪探测 → 置系统代理
   ✅ 已连接，可上网
```

**从安装到上网 = 2 次操作。** 这与 v1.0 一致（那是 MoneyFly 的立足点），
但**不再以此为借口删减任何 Clash Mi 能力**。

### 1.5.2 进阶使用（Clash Mi 原有路径完整保留）

```
用户想改 DNS / TUN / 分流 / 规则 / 代理组
        ↓
首页 → 内核设置 → DNS / TUN / TLS / 嗅探 / Geo RuleSet / 分流模板 / 覆写
        ↓
首页 → 我的配置 → 编辑配置 → 覆写设置（自定义覆写 / 追加覆写）
        ↓
首页 → 代理 → 选代理组 → 选节点 / 测速 / 排序
        ↓
首页 → 网络检测（DNS / TUN / 代理 / 路由表四段诊断）
```

> **这两条旅程必须同时完好。** 前者服务 90% 的付费用户，后者服务剩下 10% 的进阶用户与
> 客服排障场景 —— 后者正是"能不能少一次工单"的关键。

## 1.6 与两个参考项目的关系

### 1.6.1 事实核查结论

| 维度 | clashmi-main | mysoftware/moneyfly |
|---|---|---|
| Dart 文件数 | 147 | 112 |

| CI | ❌ **完全没有**（`.github/` 只有 issue 模板） | ✅ 完整（Android 分 ABI + AAB / Windows exe+zip / macOS arm64+x64+universal / iOS IPA） |

### 1.6.2 决策：**外观与能力取 Clash Mi，业务与内核工程取 MoneyFly**

> **决策 ADR-001（v2.0 修订）**
>
> Mclash 的**表现层与能力层**取自 `clashmi-main`：
> 100% 沿用其设计系统（Material 3 + `#293CA0` + 方角 + 高密度列表 + 单页滚动首页 +
> `GroupScreen` 声明式设置引擎 + Card/ListTile/BottomSheet/SimpleDialog 四元件），
> 以及其**全部代理能力**（仅移除面板与二维码工具 2 项）。
>
> Mclash 的**内核集成层、构建发布链路、以及与后台交互的业务层**取自 `mysoftware/moneyfly`：
> 它已在本机验证可构建可发布，且已满足自动拉订阅 / 自动测速 / 一键连接三项要求。
>
> **v1.0 的错误**：v1.0 以 moneyfly 为基线"改造 UI"，并列出"明确不做"清单砍掉 Clash Mi 的
> 配置/分流/规则/代理组/同步等能力。**这是错的** —— Clash Mi 的价值恰在那套能力与那套界面，
> 而 moneyfly 的价值在于可构建的内核工程和业务闭环。正确做法是**保留 clashmi 的表现层与能力层，
> 把 moneyfly 当作内核与业务的"引擎"接进去**。

## 1.7 术语表

| 术语 | 含义 |
|---|---|
| **内核 / Core** | mihomo（MetaCubeX/mihomo，原 Clash.Meta）。**不使用 fork**，一律用官方源码/官方预编译产物 |
| **AAR** | `libmihomo.aar` —— 官方 mihomo 经 `gomobile bind` 编译的 Android 库，仓库 `moneyfly004/mihomo-lib` |
| **订阅拉取** | 客户端用后台下发的 `subscribe_url` 取回 Clash YAML / base64 / 链接列表，解析成节点 |
| **占位节点** | 后台在账号到期/禁用时下发的**虚假节点**（`server: baidu.com`，名字带 📢⏰📱💬 等 emoji）。客户端必须识别并过滤，且**必须用它覆盖**本地缓存 |
| **准入闸门** | `AccountService` 对「到期 / 订阅停用 / 账号禁用 / 设备被踢」的统一判定，位于连接之前 |
| **一键连接** | 用户拨动开关后完整链路：准入判定 → 生成 YAML → 启动内核 → 就绪探测 → 置系统代理 |
| **就绪探测** | 不能只看 Clash API 返回 200；还需本地端口（mixed 入站口）真的有人监听 |
| **配置（Profile）** | Clash Mi 的核心概念：一个 mihomo YAML 配置。MoneyFly 订阅落地后成为其中一条配置 |
| **覆写（Patch）** | Clash Mi 的配置补丁机制：原始配置 ← 自定义覆写 ← App 覆写 |
| **兼容版内核** | 官方 `*-compatible` 构建，不要求 AVX2/v3 指令集，用于老 Intel CPU / Rosetta / 老 AMD CPU |
| **开发者模式** | 关于页长按「版本」切换；打开后显示隐藏的手动导入入口与开发者项 |
